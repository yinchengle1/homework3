1. Toy ECC Encryption and Decryption

Encrypt a message to display the public key, ephemeral point and ciphertext.

Main steps

  1. Generate private key d and public key Q = dG.
  2. Choose ephemeral k, calculate C1 = kG and shared point S = kQ.
  3. Derive a demonstration XOR mask from S and encrypt the message bytes.
  4. Decrypt by computing S = dC1 and applying the same mask.

4. Attack on Restricted ECC Private Keys

Enumerate candidate private keys and compare candidate public points d′G with the recipient's public key Q. This works here because the private-key interval is deliberately small.

Run the search to see how many candidates are checked.

Attack procedure

  1. Obtain the recipient public key Q.
  2. Compute G, 2G, 3G, …, NG.
  3. Stop when a candidate point matches Q.
  4. Use the recovered key with the ephemeral point to derive the shared point.

5. Comparison: ECC vs. Caesar Cipher

AspectToy ECCCaesar
EncryptionElliptic-curve multiplication and a shared-point-derived mask.Simple alphabetic shift.

Discussion

  • Caesar statistical attack: exploits language properties, such as frequent letters, to rank possible shifts.
  • Toy ECC attack: exploits the small private-key range; it does not require language statistics.
  • Proper ECC: exhaustive search over a sufficiently large private-key space is computationally infeasible, although implementation flaws, weak randomness or side channels can still cause vulnerabilities.

Alternative approaches

  • Caesar exhaustive search tests all 26 keys and is a useful baseline.
  • Letter-frequency analysis ranks likely keys using expected language distributions.
  • N-gram scoring evaluates common letter sequences and can improve plaintext ranking.
  • ECC attacks may target weak randomness, side channels or protocol mistakes rather than the underlying curve mathematics.
Conclusion

The Caesar cipher is vulnerable because of its small key space and predictable language statistics. The toy ECC experiment is vulnerable because the private key is restricted. A secure system requires an appropriate key space, a sound construction, strong randomness and correct implementation.
